Inside a 24/7 software factory

The developer can leave for the night while one agent writes a change, two others review it, and another runs the tests. What keeps a change moving when the agent that needs to act next is asleep?

Engram is the shared work record. It keeps the task, its owner and the evidence for a decision. TermAl runs the agents and delivers the messages that bring them back to work. The agents use both tools to develop the tools themselves.

Greg Lapinski · November 2026

Who keeps the work moving overnight?

The developer usually gives a goal to the Assistant. The Assistant sends it to the coordinator for that project. The coordinator divides the work into tasks and selects a coder for each task. If the work involves two projects, the coordinators speak directly to each other.

A coder can finish a turn while its change is under review. The task record identifies the version being reviewed. The host keeps the reviewers’ results and wakes the agent waiting for them. If that agent resumes after an interruption, it can recover the existing review and its results. Starting another pair of reviewers could give two teams responsibility for the same decision.

One review stalled after both reviewers finished. Follow the messages in The review that could wait forever.

Each team has an integrator who puts the checked version on the main branch. An evaluator compares the evidence with the original request. The Consultant gives a second opinion when a design needs one.

When a coordinator has a result or needs a decision, the Assistant takes the report or question back to the developer. The developer can also speak directly to the agent responsible for a task. The other teams can continue their work during that discussion.

The same rules for each goal

The team has written rules for design, changes to code, tests, communication and operations. The rules tell each agent what to do and what to record. The next agent uses this record to continue the task.

What the next coder can start now

While one change runs through the full test suite, another coder can prepare the next one. Each package identifies the Git commit and the exact files it contains. It includes tests that exercise the change and a record of which checks are still due. The coordinator names the owner of the package and who will notify that owner when the next result arrives.

In one shift, the Engram coordinator reported four such candidates behind a change undergoing its full test run. One had cleared both reviewers. Another had passed its Mac tests and was waiting for results from other machines. All three coders already had work, so the coordinator stopped at four. A longer queue would give the main branch more time to move ahead of the prepared changes.

The TermAl coordinator described a different starting point. A logging change was waiting for a test, and two later tasks were still on the list. The coordinator assigned process limits to one coder and the connection to Engram to another. Each could send a short design for review and develop the change in a separate Git worktree. Only the edits that connected those pieces in main.rs needed the same integrator, one at a time.

How the work continues between sessions

An agent can stop before the team completes a goal. Engram keeps the task records. Each record identifies the agent responsible for the task. The record also contains decisions and questions that still have no answer. A new agent can read the record and continue the task.

TermAl runs the agent sessions and sends messages between them. The Engram team and the TermAl team use these two tools. Each team has a coordinator, coders and an integrator. For a change to the two projects, the coordinators can send messages directly to each other.

What travels between machines?
Data that goes between computers
A remote test request identifies the code to test. The runner returns its result to the agent that requested it. Moving the task record is a separate operation, described in the study of two machines editing one task.
Data and permissions on each computer
Task claims and permissions to do, review or integrate work stay on the local computer. Git worktrees, build files and temporary files also stay on that computer.

Decisions that stay with the developer

The developer chooses the goals and can change their order, settle a design question or examine a particular change. A coordinator brings back the decisions that need that authority. The other teams can keep working while one question is open.
